# RaiseTechタイムライン 要件定義書

機能の詳細は [機能定義書](./FEATURES/機能定義書.md)（ディレクトリ名 `FEATURES`＝Functional Requirements。`FUTURES` ではない）、画面は [画面仕様書](./screens.md)、データは [ER図](./er.md)、技術は [技術スタック](./tech-selection.md) を参照する。開発開始後に足した判断は [開発開始後の仕様追加・変更](./dev-changes.md)。

## 1. 概要・背景・目的

### 概要

本課題の作品は **テキストベースのSNS** である。X（旧Twitter）のタイムラインのように、短い文章と任意の画像を投稿し、他のユーザーがコメントといいねを付けられる。システム名称は **RaiseTechタイムライン**。

### 背景

初級編の最終課題では、ホテル・会社の受付向け **お問い合わせアプリ**（おうち受付）を作った。受付担当と来客という役割が分かれていた。

中級編では **3つ目のアプリ** として、利用者同士が同じ立場でやり取りするSNSに入る。受講生や個人が、複数アカウントで投稿し合う場を学習用に用意する。本物のXを真似しすぎず、学習に必要な核だけを残す。

### 目的

- 複数の受講生（または個人）が、同じタイムラインで投稿を見られる
- 本文と画像で投稿できる
- 第三者がコメント・いいねでき、件数が一覧でも分かる
- ユーザー名で検索でき、投稿・コメントのユーザー名からプロフィールへ進んでフォローできる
- 気になる人をフォローし、フォロー中の投稿だけも見られる
- ログインした本人だけが投稿・コメント・いいね・フォローできる
- 中級編で扱う認証・認可、N+1、テスト、ログ、CI/CD、AWS（無料枠）の土台になる

## 2. 対象ユーザー

| アクター | 説明 |
|----------|------|
| 未ログイン利用者 | 新規登録とログインだけできる |
| ログイン済み利用者（受講生／個人） | 投稿、コメント、いいね、フォロー、タイムライン閲覧 |
| 他の利用者（第三者） | 同じ投稿にコメント・いいねする相手。フォローする／される相手 |

管理者画面や運営ロールは今回作らない。全員が同じ権限の利用者である。

## 3. 機能要件（MVP）

今回作る機能は次の7つに絞る。ログインを成立させるため、新規登録とログアウトはログイン機能に含める。投稿そのものはタイムライン機能に含める。

| # | 機能 | 内容 |
|---|------|------|
| 1 | ログイン | メールアドレスとパスワードで入る。未登録なら新規登録する。ログアウトできる |
| 2 | タイムライン | 「すべて」と「フォロー中」を切り替える。本文・投稿者・日時・いいね数・コメント数を出す |
| 3 | コメント | 投稿に対して第三者がコメントする。件数を見せる。コメントのユーザー名からプロフィールへ |
| 4 | いいね | 投稿に対して第三者がいいねする。同じ人は1投稿につき1回。件数を見せる |
| 5 | 画像投稿 | 投稿に画像を1枚添えられる。画像なしのテキスト投稿も可 |
| 6 | フォロー | 他のユーザーをフォロー／解除する。フォロワー数・フォロー数を出す。自分はフォローできない |
| 7 | ユーザー検索 | ユーザー名で検索する。結果からプロフィールへ進み、フォローできる |

## 4. 非機能要件

- パスワードは保存時にハッシュする。平文で残さない
- 未ログインでは投稿・コメント・いいね・フォローできない（認可）
- タイムラインのいいね数・コメント数は、投稿件数分の追加クエリ（N+1）を避ける
- フォロー中タイムラインは、フォロー先を1件ずつ問い合わせない
- 画像はJPEG / PNG / WebP、1枚あたり5MBまで
- 学習用。インターネットへの常時公開はしない。AWSは無料枠の範囲で後から触れる

## 5. 画面一覧

| 画面 | 役割 | 主な利用者 |
|------|------|------------|
| ログイン | メールとパスワードで入室 | 未ログイン |
| 新規登録 | アカウントを作る | 未ログイン |
| タイムライン | 投稿の作成と一覧（すべて／フォロー中）。投稿者名クリックでプロフィール | ログイン済み |
| 投稿詳細 | 本文・画像・コメント。コメントのユーザー名クリックでプロフィール | ログイン済み |
| プロフィール | その人の投稿一覧、フォロー／解除、件数 | ログイン済み |
| フォロー一覧 | フォロー中／フォロワーの名前一覧 | ログイン済み |
| ユーザー検索 | ユーザー名で検索した結果 | ログイン済み |

画面の項目と遷移は [画面仕様書](./screens.md) を参照する。

## 6. スコープ外（今回作らない）

- ハッシュタグ検索
- リポスト、引用、ブックマーク
- ダイレクトメッセージ
- 動画・複数枚画像・GIF
- 管理者画面、通報、BAN
- パスワード再設定メール
- アプリの本番公開（常時稼働のURL）
- WebSocket で投稿の作成・編集・削除を一件ごとに全員へ通知すること（人数が増えると通知が増え、使いづらくなる）

人を見つける入口は、ヘッダーのユーザー名検索と、投稿・コメントのユーザー名クリック。フォローしていない人の投稿も「すべて」で見られるので、受講生同士の確認は空にならない。

画面の技術は [技術スタック](./tech-selection.md) のとおり、にゃんこタスク（React 19.2.8 / Vite 6.4.3 / TypeScript 5.7.3）と同じバージョンを使う。

## 7. 中級編で後から触れること（予告）

実装に入ってから、次を学習トピックとして扱う。要件の核は変えず、品質と運用の話として足す。

| トピック | このアプリでの意味 |
|----------|-------------------|
| 認証・認可 | ログイン状態の確認。他人の投稿削除は不可 |
| N+1問題 | 投稿一覧でいいね数・コメント数をまとめて取る |
| テスト | ログイン、投稿、いいね・フォローの重複防止などを自動で確認 |
| ログ | ログイン失敗や投稿エラーを残す |
| CI/CD | テストが通ったら取り込む |
| AWS（無料枠） | 作りっぱなしにしない。課金リソースは置かない |

## 8. 受け入れ基準

- [ ] 複数ユーザーがそれぞれ登録・ログインできる
- [ ] ログインした人がテキスト投稿できる
- [ ] 投稿に画像を1枚付けられる（付けなくても投稿できる）
- [ ] タイムラインの「すべて」に全ユーザーの投稿が新しい順で出る
- [ ] 投稿に成功したら、タイムライン先頭にすぐ出る（再読み込みボタンは不要）
- [ ] 古い投稿は「もっと見る」ボタンではなく、下スクロール（無限スクロール）で続く
- [ ] 他のユーザーをフォロー／解除でき、自分はフォローできない
- [ ] 「フォロー中」には、フォローした人と自分の投稿だけが出る
- [ ] プロフィールにフォロー数・フォロワー数が分かる
- [ ] 第三者がコメントでき、件数がタイムライン上で分かる
- [ ] 第三者がいいねでき、件数がタイムライン上で分かる
- [ ] 同じユーザーが同じ投稿にいいねを重複して付けられない
- [ ] ユーザー名で検索でき、結果からプロフィールへ進める
- [ ] 投稿およびコメントのユーザー名をクリックするとプロフィールが開き、フォローできる
- [ ] 未ログインでは投稿・コメント・いいね・フォローできない
