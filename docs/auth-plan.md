## 1. ゴール

| できること | できないこと（今回やらない） |
|------------|------------------------------|
| 新規登録 | タイムライン、投稿、コメント、いいね |

ログイン成功先: **Hello World の仮ページ**。あとからタイムラインに差し替える。

## 2. 画面（今回3つ）

```
未ログイン → ログイン ⇄ 新規登録
                ↓ 成功（JWT）
            Hello World（仮）
                ↓ ログアウト
              ログイン
```

| 画面 | 役割 |
|------|------|
| ログイン | メール＋パスワード。失敗時は理由を出し、パスワード欄を空にする |
| 新規登録 | ユーザー名・表示名・メール・パスワード・確認 |
| Hello World | ログインできたことの確認だけ。中身は空でよい |

未ログインで Hello World 相当を開いたらログインへ戻す（トークン無し／壊れているときは `GET /api/me` が 401）。

## 3. API（今回3本＋ヘルス）

| 方法 | パス | 誰が使う | 成功時 |
|------|------|----------|--------|
| POST | `/api/signup` | 未ログイン | 201 `{ token, user }` |
| POST | `/api/login` | 未ログイン | 200 `{ token, user }` |
| GET | `/api/me` | ログイン済み（Bearer） | 200 `{ user }` |
| GET | `/api/health` | 起動確認 | `{ ok: true }` |

`user` にパスワードは入れない。保存は `password_digest`（ハッシュ）だけ。

## 4. バリデーション（機能定義書どおり）

| 項目 | 規則 |
|------|------|
| ユーザー名 | 3〜20文字、半角英小文字・数字・`_`。一意 |
| 表示名 | 1〜20文字 |
| メール | 形式チェック。一意 |
| パスワード | 8文字以上。確認と一致 |
| ログイン失敗 | 「メールアドレスまたはパスワードが違います」。パスワード欄を空にする |

## 5. 認証と認可の分け方

1. **認証** … メールとパスワードが合っているか。合えば JWT を発行する（中にユーザー ID と username）
2. **認可** … 以降の API は `Authorization: Bearer <token>` が無いと 401。Hello World はトークンがあるときだけ出す
3. 画面はトークンを `sessionStorage` に置く。ログアウトで消す

秘密鍵は `.env` の `JWT_SECRET`。Git に書かない。有効期限は 24 時間で足りる。

## 6. 作業の順番

1. `users` テーブル（email / username / display_name / password_digest）
2. パスワードのハッシュ化（平文で保存しない）
3. `POST /api/signup` → ユーザー作成 → JWT 発行
4. `POST /api/login` → 照合 → JWT 発行
5. `requireAuth` ミドルウェア → `GET /api/me`
6. 画面: 登録・ログイン・エラー表示
7. 成功後は Hello World。ログアウトでトークン削除
