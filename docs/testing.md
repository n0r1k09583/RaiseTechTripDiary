# テストの考え方（ブラックボックス / ホワイトボックス）

テストは「たくさん書く」前に **パターンとケースを決める**。このリポジトリでは次の対応にする。

| 見方 | 何を正とするか | 主に置く場所 |
|------|----------------|--------------|
| ブラックボックス | 機能定義・画面・OpenAPI（入力と結果だけ） | コントローラ結合（`*ApiTest`）、画面コンポーネント、サービスでも境界値 |
| ホワイトボックス | 実装の分岐・条件・SQL | サービス単体、MyBatis（H2）、JWT、画像保存 |

本番の SQLite（`data/tripdiary.db`）には書かない。DB 系はメモリの **H2**。H2 2.x に `MODE=SQLite` は無いので、テスト用 DDL は `backend/src/test/resources/db/h2/`、本番 Flyway は SQLite のまま。毎回の自動実行に E2E も k6 も載せない。CI は `.github/workflows/ci.yml`。

`@MapperH2Test` は `com.raisetech.tripdiary.support` に置く（`mapper` パッケージだと MyBatis が Mapper と誤認し、`@WebMvcTest` が壊れる）。

## ブラックボックス（仕様からケースを出す）

コードを見ずに、「入力の種類」と「期待する結果」を決める。

### 使うパターン

| パターン | このアプリでの使い方 |
|----------|----------------------|
| 同値分割 | 正しい入力は代表1つ。不正も種類ごとに1つ（形式不正 / 空 / 重複 / 権限なし） |
| 境界値 | 長さ・件数・サイズは **境界の内側と外側** を取る（n-1, n, n+1） |
| デシジョンテーブル | 条件の組み合わせ（自分か他人か、画像ありか、タブは all か） |
| 状態遷移 | ログイン → リフレッシュ（古い refresh は無効）→ ログアウト |
| エラー推測 | 空 Content-Type、パス区切り付きファイル名、JSON 壊れ |

同値分割で「不正」を1つにまとめると、ユーザー名が短いのか記号なのか分からない。**理由が違う不正は別クラス**にする。

### 境界値の表（仕様）

| 項目 | 無効（下） | 有効の端 | 有効の端 | 無効（上） |
|------|------------|----------|----------|------------|
| ユーザー名 | 2文字、記号 | 3 | 20 | 21 |
| 表示名 | 空（trim 後） | 1 | 20 | 21 |
| パスワード | 7 | 8 | （上限なし） | — |
| 投稿本文 | 空 / 空白のみ | 1 | 280 | 281 |
| コメント | 空 / 空白のみ | 1 | 140 | 141 |
| 画像サイズ | — | 5MBちょうどは可 | — | 5MB+1 |
| 一覧 `limit` | 0 は実装で 1 に丸める | 1 | 50 | 51 は 50 に丸める |

画像形式の同値クラス: JPEG / PNG / WebP（有効）、GIF・空タイプ（無効）。

認可のデシジョン:

| 投稿がある | 自分の投稿 | 期待 |
|------------|------------|------|
| いいえ | — | 404 |
| はい | いいえ | 403 |
| はい | はい | 200 / 204 |

ログイン失敗は「ユーザーがいない」も「パスワード違い」も **同じ 401 文言**（仕様。ユーザー列挙を防ぐ）。ブラックボックスでは1クラス。ホワイトボックスでは両方の分岐を踏む。

## ホワイトボックス（実装からケースを出す）

コードの **if / 正規化 / SQL の `<if>`** を見て、通っていない枝を足す。

| 枝 | なぜ要るか |
|----|------------|
| ユーザー名 `toLowerCase` のあとで正規表現 | `ABC` は2文字相当ではなく、小文字化後に判定する |
| `confirm` が空なら `passwordConfirm` | 別名の入力経路 |
| `tab` が `following` 以外は `all` | 未知タブを落とさない |
| `before*` は **両方揃ったときだけ** 古いページ | 片方だけならページングしない |
| `after*` は新しい差分。`hasMore` は付けない | fetch が `size` のまま |
| `limit` の `Math.min/max` | 0 と 51 |
| 画像 `Content-Type` を lower-case | `IMAGE/JPEG` は通す |
| JWT の `typ == access` | refresh を Bearer に付けても 401 |
| 投稿 `user_id == null` | 所有チェックの片方の枝 |
| コメント件数は同じ SELECT のサブクエリ | N+1 にしないことの実装確認 |
| 同じ `created_at` なら `id` でタイブレーク | XML の OR 条件 |

ブラックボックスの「他人は 403」だけでは、`userId == null` の枝は落ちない。

## 層とパターンの対応

| 層 | ボックス | 例 |
|----|----------|-----|
| コントローラ（モックサービス） | 黒 | HTTP と `{ status, code, error }` |
| サービス（モック Mapper） | 白＋境界 | 長さ、所有、タブ正規化 |
| MyBatis + H2 | 白 | `following`、`before`/`after`、件数サブクエリ、UNIQUE |
| `*ApiTest`（H2 で起動） | 黒 | 画面担当と同じパスで異常系 |
| フロントコンポーネント | 黒 | 空送信で API を呼ばない、401 でログアウト |
| `api.ts` | 黒 | 401 の `error`、通信失敗、204 |

フロントの textarea は `maxLength={280}` なので、281 文字は **画面からは入力できない**。281 は API（ブラックボックスの上側境界）で見る。

## 異常系を先に置く理由

TDD の Red は、成功例より **境界の外側と権限エラー** の方が契約がはっきりする。Swagger に書いた 400 / 401 / 403 / 413 は、ブラックボックスの期待値そのもの。

品質チェック: `backend` で `.\mvnw.cmd test`（Checkstyle は validate で一緒に走る）。ルールは `CLAUDE.md`。ログは [logging.md](./logging.md)。遅さ・負荷・ブラウザの描画は毎回回さない。[パフォーマンステストの計画](./performance.md)（P95、後始末）。
