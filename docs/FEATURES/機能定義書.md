**ディレクトリ名:** `docs/FEATURES/`

**日本語名:** 機能定義書

## F-01 ログイン機能

### 目的

複数ユーザーを区別する。誰が投稿・コメント・いいねしたかを残す。

### 含めるもの

| 操作 | 内容 |
|------|------|
| 新規登録 | ユーザー名、表示名、メールアドレス、パスワードを登録する |
| ログイン | メールアドレスとパスワードでセッションを開始する |
| ログアウト | セッションを終了し、ログイン画面へ戻す |

### 基本フロー（ログイン）

1. 未ログインでアプリを開くとログイン画面になる
2. メールアドレスとパスワードを入力して送信する
3. 正しければタイムラインへ進む
4. 間違っていればエラーを出し、パスワード欄を空にする

### 基本フロー（新規登録）

1. ログイン画面から新規登録へ進む
2. ユーザー名（3〜20文字、半角英小文字・数字・`_`）、表示名（1〜20文字）、メール、パスワード（8文字以上）を入力する
3. ユーザー名とメールが未使用ならユーザーを作成し、ログイン状態でタイムラインへ進む
4. ユーザー名またはメールが既にあればエラーにする

### 例外

- 未入力、形式不正は保存しない
- パスワードはハッシュして保存する。画面にもログにも出さない
- 未ログインでタイムライン等を開いたらログイン画面へ戻す

### 認可の考え方（中級で深める）

- 認証: 「この人は登録済みか」
- 認可: 「この人が投稿・コメント・いいね・フォローしてよいか」「他人の投稿を消してよいか」
- MVPでは、消せるのは自分の投稿と、自分のコメント（コメントは後から）にする。他人の投稿は消せない

## F-02 タイムライン機能

### 目的

投稿の作成と、時系列の一覧。一覧は2種類ある。

| タブ | 出す投稿 |
|------|----------|
| すべて | 全ユーザーの投稿（受講生が互いの投稿を探す入口） |
| フォロー中 | フォローした人と、自分の投稿 |

フォローゼロでも「すべて」は空にならない。自分の投稿は「フォロー中」にも出す（自分をフォローしなくてよい）。

### 含めるもの

| 操作 | 内容 |
|------|------|
| 投稿作成 | 本文（1〜280文字）を投稿する。画像は任意（F-05）。成功したらタイムライン先頭にすぐ出す |
| 投稿編集 | 自分の投稿だけ本文・画像を直せる |
| 投稿削除 | 自分の投稿だけ消せる。確認のあと削除する。他人の投稿は消せない |
| タブ切替 | 「すべて」と「フォロー中」 |
| 一覧表示 | ユーザー名、表示名、本文、画像サムネイル、日時、いいね数、コメント数 |
| 無限スクロール | 下へスクロールすると古い投稿を続けて読む。「もっと見る」ボタンは使わない |
| 最新の取り方 | 自分の投稿・編集・削除の直後に画面を更新する。他人の変更は一定間隔で静かに取り直す。WebSocket で一件ごとに通知しない |
| ユーザー名クリック | 投稿者のユーザー名（または表示名）を押すとプロフィール（S-05）へ。そこからフォローできる |
| 詳細へ | 投稿をクリック（または「コメント」）すると投稿詳細へ |

### 一覧に必ず出す件数

複数ユーザーが使うため、第三者の反応が分かる必要がある。

- **いいね数** … その投稿についたいいねの件数
- **コメント数** … その投稿についたコメントの件数

件数は詳細を開かなくてもタイムライン上で見える。

### 並び順・読み方

- 新しい投稿が上（`created_at` の降順）
- SNS では「もっと見る」「次のページ」ボタンで続きを出すのは使いにくい。続きは **無限スクロール** で出す
- 最初は最新の数十件。画面下に近づいたら、それより古い投稿を追加取得する（ボタンは出さない）
- 自分が投稿・編集・削除したときは、そのタイミングでタイムラインを更新する（成功直後に先頭へ出す／直す／消す）
- 他の人の作成・編集・削除は、**一件ごとに通知しない**。人数が増えると通知が止まり、使いづらくなるため
- WebSocket で毎回プッシュしない。代わりに、画面を開いたままなら **一定間隔（約30秒）** で最新を静かに取り直す。タブに戻ったときも取り直してよい
- 取り直しは一覧を差し替えるだけで、トーストや件数バッジは出さない

### 実装時の注意（N+1）

投稿を50件出したあと、1件ずつ「いいね数を取る」「コメント数を取る」とクエリが100回増える。一覧では投稿と件数をまとめて取得する。「フォロー中」は `follows` を JOIN し、フォロー先を1人ずつ問い合わせない。

## F-03 コメント機能

### 目的

投稿の本文とは別に、第三者が短い返信を付けられるようにする。会話の量が件数で分かる。

### 基本フロー

1. タイムラインでコメント数または投稿本体を開く
2. 投稿詳細に、本文・画像・コメント一覧が出る
3. コメント欄（1〜140文字）を送信する
4. 自分のコメントが一覧に増え、コメント数が1増える
5. タイムラインに戻ると、増えた件数が反映されている

### ルール

- ログイン済みなら、自分の投稿にも他人の投稿にもコメントできる
- コメントした人の **ユーザー名（と表示名）を出す。押すとプロフィールへ**。プロフィールからフォローできる
- 空コメントは不可
- コメントの編集は作らない
- 自分のコメントだけ削除できる（任意だがあると検証しやすい）

### 件数

`comments` テーブルの `post_id` ごとの件数。削除したら件数も減る。

## F-04 いいね機能

### 目的

第三者が「見た・共感した」を1タップで残す。誰が何件押したかが分かる。

### 基本フロー

1. タイムラインまたは詳細で、ハート（いいね）を押す
2. 未いいねなら1件増え、自分がいいねした見た目になる
3. もう一度押すと取り消し、件数が1減る（トグル）

### ルール

- 1ユーザー × 1投稿につきいいねは最大1件（一意制約）
- 自分の投稿にもいいねできる
- いいねした人の一覧はMVPでは出さなくてよい（件数と自分の状態だけでよい）

### 表示

| 場所 | 出すもの |
|------|----------|
| タイムライン | 件数。自分がいいね済みなら塗りつぶし |
| 投稿詳細 | 同じ |

## F-05 画像投稿機能

### 目的

テキストだけでなく、1枚の画像を添えて投稿できるようにする。

### ルール

- 画像は任意。テキストだけでも投稿できる
- 1投稿につき画像は最大1枚
- 形式: JPEG / PNG / WebP
- サイズ: 5MBまで
- タイムラインでは縮小表示、詳細では大きく表示
- 画像ファイルそのものはDBに入れず、保存先のパスだけDBに持つ

### 例外

- 非対応形式・サイズ超過は投稿せず、理由を出す
- 画像の読み込みに失敗しても本文は出せる

## F-06 フォロー機能

### 目的

気になる受講生だけを追えるようにする。第三者とのつながりが、フォロー数・フォロワー数で分かる。

### プロフィールへ進む入口（すべてからフォローできる）

| 入口 | 操作 |
|------|------|
| タイムラインの投稿 | 投稿者のユーザー名をクリック → プロフィール → フォロー |
| 投稿詳細の投稿者 | 同上 |
| コメント | コメントした人のユーザー名をクリック → プロフィール → フォロー |
| ユーザー検索 | 検索結果のユーザー名をクリック → プロフィール → フォロー |
| フォロー／フォロワー一覧 | 名前をクリック → プロフィール → フォロー |

### 基本フロー（フォローする）

1. 上記いずれかで相手のプロフィールを開く
2. 「フォロー」を押す
3. ボタンが「フォロー中」に変わり、相手のフォロワー数が1増える
4. 自分のタイムライン「フォロー中」に、相手の投稿が出る

### 基本フロー（解除する）

1. プロフィールの「フォロー中」を押す（または同じボタンのトグル）
2. フォローが外れ、相手のフォロワー数が1減る
3. 「フォロー中」タブから、その人の投稿が消える（「すべて」には残る）

### ルール

- 自分自身はフォローできない。自分のプロフィールにフォローボタンは出さない
- 1ユーザー × 1相手につきフォローは最大1件（一意制約）
- 相手が自分をフォローしていなくてもフォローできる（片方向でよい。相互は2行）
- 未ログインではフォローできない
- フォローしていない人の投稿も「すべて」とプロフィールでは見られる（非公開アカウントは作らない）

### 表示

| 場所 | 出すもの |
|------|----------|
| 他人のプロフィール | フォロー／フォロー中ボタン、フォロー数、フォロワー数 |
| 自分のプロフィール | ボタンなし。フォロー数・フォロワー数だけ |
| フォロー一覧 | フォロー中の人のユーザー名 |
| フォロワー一覧 | 自分（またはその人）をフォローしている人のユーザー名 |

件数は 0 でも出す。

## F-07 ユーザー検索機能

### 目的

ユーザー名で人を見つけ、プロフィールを開いてフォローする。ハッシュタグ検索は作らない。

### 基本フロー

1. ヘッダーの検索欄にユーザー名の一部または全部を入れる
2. 一致するユーザーが一覧で出る（ユーザー名の部分一致。大文字小文字は区別しない）
3. 行のユーザー名（または表示名）を押すとプロフィールへ進む
4. プロフィールでフォローできる

### ルール

- 検索対象は **ユーザー名**（`username`）。表示名だけの一致は必須にしない
- 未入力で検索したら結果を出さず、案内を出す
- 0件なら「該当するユーザーはいません」
- 自分も検索結果に出てよい。自分の行からプロフィールは開けるが、フォローボタンは出ない
- ログイン済みのみ使える
