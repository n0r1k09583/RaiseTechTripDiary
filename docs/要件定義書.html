1. 初級編の振り返りと本書の位置づけ

初級編の最終課題では、ホテル・会社の受付向けお問い合わせアプリを作った。受付担当と来客という役割が分かれ、到着・帰宅・通話が中心だった。

中級編では、利用者同士が同じ立場でやり取りするテキストベースのSNSに入る。本書はその要件定義である。機能一覧・画面設計・ER図を先に固め、そのあと開発に進む。

画面の入口はタイムラインだけとする。課題の表示名は課題提出、ログイン後の見出しも「課題提出」「タイムライン」とする。受付やタスク管理の画面は置かない。

RaiseTechタイムライン　要件定義書1

2. 概要・背景・目的

2.1 概要

本課題の作品はテキストベースのSNSである。X（旧Twitter）のタイムラインのように、短い文章と任意の画像を投稿し、他のユーザーがコメントといいねを付けられる。システム名称はRaiseTechタイムライン。画面上の表示名は「課題提出」「タイムライン」とする。

2.2 背景

受講生や個人が学習用に使う。本物のXを真似しすぎず、学習に必要な核（ログイン、投稿の流れ、第三者の反応）だけを残す。一人用のメモアプリではなく、複数ユーザーが同時に使う前提で設計する。

2.3 目的

  • 複数の受講生（または個人）が、同じタイムラインで投稿を見られる
  • 本文と画像で投稿できる
  • 第三者がコメント・いいねでき、件数が一覧でも分かる
  • ユーザー名で検索でき、投稿・コメントのユーザー名からプロフィールへ進んでフォローできる
  • 気になる人をフォローし、フォロー中の投稿だけも見られる
  • ログインした本人だけが投稿・コメント・いいね・フォローできる

4. 機能要件（機能一覧）

今回作る機能は次の7つに絞る。ログインを成立させるため、新規登録とログアウトはログイン機能に含める。投稿そのものはタイムライン機能に含める。

ID機能内容
F-01ログインメールアドレスとパスワードで入る。未登録なら新規登録する。ログアウトできる
F-02タイムライン「すべて」と「フォロー中」を切り替える。本文・投稿者・日時・いいね数・コメント数を出す
F-03コメント投稿に対して第三者がコメントする。件数を見せる。コメントのユーザー名からプロフィールへ
F-04いいね投稿に対して第三者がいいねする。同じ人は1投稿につき1回。件数を見せる
F-05画像投稿投稿に画像を1枚添えられる。画像なしのテキスト投稿も可
F-06フォロー他のユーザーをフォロー／解除する。フォロワー数・フォロー数を出す。自分はフォローできない
F-07ユーザー検索ユーザー名で検索する。結果からプロフィールへ進み、フォローできる

4.1 F-01 ログイン

複数ユーザーを区別し、誰が投稿・コメント・いいねしたかを残す。ユーザー名（3〜20文字、半角英小文字・数字・_、一意）、表示名（1〜20文字）、メールアドレス、パスワード（8文字以上）で新規登録する。パスワードはハッシュして保存し、平文では残さない。未ログインでタイムライン等を開いたらログイン画面へ戻す。ログイン成功後はタイムラインを出す。

4.2 F-02 タイムライン

一覧は2種類ある。すべては全ユーザーの投稿、フォロー中はフォローした人と自分の投稿。新しい投稿が上。一覧には投稿者名、本文、画像サムネイル、日時に加え、いいね数とコメント数を必ず出す。詳細を開かなくても、第三者の反応が分かるようにする。フォローゼロでも「すべて」は空にならない。

投稿は作成・編集・削除ができる（自分の投稿だけ）。続きは「もっと見る」ボタンではなく、無限スクロールで古い投稿を足す。自分が投稿・編集・削除した内容は押した直後に一覧へ出す。他人の作成・編集・削除は一件ずつ通知せず、約30秒おき（またはタブに戻ったとき）に静かに取り直す。

4.3 F-03 コメント

ログイン済みなら、自分の投稿にも他人の投稿にもコメントできる（1〜140文字）。コメントした人のユーザー名と日時を出す。ユーザー名を押すとプロフィールへ進み、そこでフォローできる。空コメントは不可。件数は comments テーブルの投稿ごとの行数とし、タイムライン上でも「コメント n件」と出す。0件のときも隠さない。

4.4 F-04 いいね

ハートを押すと付き、もう一度押すと取り消す（トグル）。1ユーザー×1投稿につき最大1件とし、データベースの一意制約で重複を防ぐ。自分の投稿にもいいねできる。いいねした人の一覧は今回出さず、件数と自分の押済み状態だけでよい。

4.5 F-05 画像投稿

画像は任意。1投稿につき最大1枚。JPEG / PNG / WebP、5MBまで。ファイル実体は uploads 等に置き、データベースにはパスだけ持つ。非対応形式やサイズ超過は投稿せず、理由を出す。

4.6 F-06 フォロー

他人のプロフィールからフォロー／解除する。自分自身はフォローできない。片方向でよく、相互フォローは2行になる。1ユーザー×1相手につき最大1件とし、一意制約で重複を防ぐ。プロフィールへ進む入口は、(1) タイムラインの投稿者ユーザー名、(2) コメントのユーザー名、(3) ユーザー検索の結果、(4) フォロー／フォロワー一覧。いずれもプロフィールでフォローできる。

4.7 F-07 ユーザー検索

ヘッダーの検索欄にユーザー名の一部または全部を入れる。部分一致（大文字小文字は区別しない）。結果のユーザー名を押すとプロフィールへ進み、フォローできる。ハッシュタグ検索は作らない。

5. 非機能要件・技術構成

5.1 非機能要件

  • パスワードは保存時にハッシュする。平文で残さない
  • 未ログインでは投稿・コメント・いいね・フォローできない（認可）
  • 他人の投稿は編集・削除できない
  • タイムラインのいいね数・コメント数は、投稿件数分の追加クエリ（N+1）を避ける
  • フォロー中タイムラインは、フォロー先を1件ずつ問い合わせない
  • 画像は JPEG / PNG / WebP、1枚あたり 5MB まで
  • 学習用。インターネットへの常時公開はしない。AWS は無料枠の範囲で後から触れる

5.2 技術構成

画面は React と Vite で作り、API は Spring Boot で受ける。データは SQLite に保存する。認証は JWT（アクセス＋リフレッシュ）とする。

認証アクセストークン（15分）＋リフレッシュトークン（7日、DB保存）ログアウトで破棄する

7. ER図・データ項目

複数ユーザーが投稿し、第三者がコメント・いいね・フォローを付ける。件数は comments・likes・follows の行数で出す。テーブルに件数列は持たない（今回は都度集計）。

users 1 ─── * posts （投稿する） users 1 ─── * comments （コメントする） users 1 ─── * likes （いいねする） users 1 ─── * follows （フォローする／される） posts 1 ─── * comments （コメントされる） posts 1 ─── * likes （いいねされる） likes は UNIQUE (post_id, user_id) follows は UNIQUE (follower_id, followee_id) follows は follower_id ≠ followee_id（自分自身は不可） posts.image_path は NULL 可（画像なし投稿）

8. スコープ外（今回作らない）

  • ハッシュタグ検索
  • リポスト、引用、ブックマーク
  • ダイレクトメッセージ

10. 受け入れ基準

  • 複数ユーザーがそれぞれ登録・ログインできる
  • ログイン成功後はタイムラインが出る
  • ログインした人がテキスト投稿できる
  • 投稿に画像を1枚付けられる（付けなくても投稿できる）
  • 自分の投稿は編集・削除できる。他人の投稿はできない
  • タイムラインの「すべて」に全ユーザーの投稿が新しい順で出る
  • 投稿に成功したら、タイムライン先頭にすぐ出る（再読み込みボタンは不要）
  • 古い投稿は「もっと見る」ボタンではなく、下スクロール（無限スクロール）で続く
  • 他のユーザーをフォロー／解除でき、自分はフォローできない
  • 「フォロー中」には、フォローした人と自分の投稿だけが出る
  • プロフィールにフォロー数・フォロワー数が分かる
  • 第三者がコメントでき、件数がタイムライン上で分かる
  • 第三者がいいねでき、件数がタイムライン上で分かる
  • 同じユーザーが同じ投稿にいいねを重複して付けられない
  • ユーザー名で検索でき、結果からプロフィールへ進める
  • 投稿およびコメントのユーザー名をクリックするとプロフィールが開き、フォローできる
  • 未ログインでは投稿・コメント・いいね・フォローできない

10.1 複数人で試す流れ

  1. Aさんが登録してテキスト投稿する
  2. Bさんが別アカウントで登録し、同じタイムラインにAの投稿が見える
  3. Bさんがいいねする → Aの画面でも件数が増える
  4. Cさんがコメントする → タイムラインの「コメント n件」が増える
  5. Aさんが画像つきで再投稿する → B・Cのタイムライン「すべて」先頭に画像が出る
  6. BさんがAさんをフォローする → Bの「フォロー中」にAの投稿が出る。Aのフォロワー数が1増える
  7. Bさんがフォローを外す → 「フォロー中」からAの投稿が消え、「すべて」には残る
  8. Cさんがヘッダーでユーザー名検索し、コメントのユーザー名からも同じプロフィールへ進めてフォローできる

確認用のデモユーザー例: 山田（@yamada）、佐藤（@hanako）、鈴木（@ichiro）。パスワードは password123。
